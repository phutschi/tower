# Credits steer the Reviewer, through opt-in probes

With three kinds, the Reviewer's kind can follow how much of each harness's
quota is left. Only the Reviewer's kind is steered: Reviewers are fresh
one-shot agents, while a lane's kind is sticky for the run and a mid-run
switch would need a handoff tower does not have. The quotas are not
comparable (5-hour and weekly windows, plan-dependent windows, a monthly
cycle), so credits act as a guard, not a race: the fixed "other kind" is
used unless its tightest window is below a threshold, then the next one.
The probes read OAuth tokens from the keychain and call undocumented or
internal endpoints that any CLI update can break, so they are off unless a
run switch turns them on, they live only in the herdr-only kit (never in
`src/`, ADR 0005), and a kind whose credits cannot be read counts as having
enough. Each choice credits made is written as a tower note.
